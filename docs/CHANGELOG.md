## [Unreleased]

### Added

- **密钥保密柜（key-vault，`vault` feature，默认随 `full` 开启）**：上游 LLM 密钥经 `POST /admin/vault/keys`（或首装时从 `api_key_env`/`api_key_envs` 指向的环境变量自动吸收）录入后以 cocoon 0.5 AEAD（AES-256-GCM/ChaCha20-Poly1305，`MiniCocoon::from_key` 逐条加密）持久化——db 构建存 `vault_keys` 表 BLOB 列（V3 迁移，三方言；`GET` 列表仅回掩码 `sk-***xxxx` 与 SHA256 指纹，零明文），无库构建（SDK 嵌入）回落加密文件柜（`~/.fluxgate/vault.bin`，临时文件 + rename 原子替换）。删除即时生效：inline key pool 热重注，柜清空时清池回退 env 兜底。主钥分层：env `FLUXGATE_MASTER_KEY`（64 hex）优先，缺失自动生成 `~/.fluxgate/vault_master.key`（Unix 0600）；**主钥丢失柜内密钥不可恢复**。明文边界：仅输入瞬间、内存使用瞬间（`secrecy::SecretString` 包装）、上游请求拼装瞬间，日志/trace/响应/持久化零明文；`reveal` 为唯一明文出口（仅供 inline 池注入）。SDK 嵌入经 `KeyStore` trait（async，`async-trait` dyn 安全）编程式使用；不开启 `vault` feature 时行为与历史逐位一致。

- **难度定档路由（三档，规则 + 进程内决策引擎融合）**：新增 `[routing.difficulty]` 配置段（默认 `enabled=false` 完全旁路，行为与历史逐位一致）。请求模型名命中 `groups` 时先做难度定档：确定性规则计分（中英双语 hard/easy 词表、数学符号密度、代码围栏、多问拆解、结构特征，文本有界 ≤2KB）+ vecboost laya 决策引擎的校准概率 P(high)（进程内直调 `EngineFactory::create` + `InferenceEngine::decide`，**不走 HTTP**）加权融合 `S = (w_clf·p + w_rule·r)/(w_clf+w_rule)`，按 `score_low`/`score_high` 阈值切 low/mid/high 三档并改写为目标抽象模型名（档位成员复用既有 `abstract_id` 分组，带内厂商选择完全复用现有 5 因子加权/亲和/LinUCB 链）；`tiers.mid` 缺省的两档退化形态支持 `mid_band_policy`（strong/cheap/nearest，平局取 high）。全部降级显性化：配置校验 V1-V7（权重全零/阈值倒置/策略非法/feature 缺失/撞名/无候选拒绝，候选集全同 warn）、laya 加载失败 → 纯规则常驻降级（F3，ERROR 限频）、单次推理失败/超时 → 该请求退纯规则（F5）、连续失败达阈值熔断 open + 半开探测恢复（F6，阈值/间隔热读）、畸形 body 特征退化（F7）、熔断 open 期直连（不再调用分类器）。观测：`/admin/metrics` 快照新增 `difficulty` 子块（fusion/rule_only/cache_hit/classifier_failed/features_degraded/breaker_opened/breaker_recovered、tier 三维分布、平均延迟）；新端点 `POST /admin/route/difficulty-explain`（S 分解/命中档/熔断状态，只读零计量副作用）；定档路径响应带 `X-Difficulty-Tier` 头。推理栈整体置于新 `difficulty-classifier` feature 后（`dep:vecboost` path 依赖，default-features=false；关闭 feature 时纯规则形态可用、w_clf>0 被启动校验拒绝）。配置校验在加载与热更两处执行（热更失败保持旧配置）：V1-V8 之外含数值域校验（负权重、阈值 ∈ [0,1]、timeout_ms 界、engine 白名单）。特征文本有界化（≤2KB 增量钳制 + 控制字符消毒——防粘贴 ANSI 转义码的正常请求被 vecboost 校验显性拒绝而误触熔断）与 body 结构长度免分配估算（封顶早停，不做全量序列化）。`routing.difficulty.classifier.model_path`/`engine`/`cache_ttl_secs` 热更列入 restart_required 提示（分类器 bootstrap 装配一次）。

- **嵌入兼容组路由（向量空间漂移三层防护）**：`POST /v1/embeddings` 从「每请求独立加权随机选厂商」改为「兼容组粘着」——首次加权选中厂商所在组被进程内 pin 表记住（首写者胜，语义对齐会话亲和），后续请求仅在组内加权选择。`ModelConfig` 新增 `dimensions` / `compat_group` 两个可选字段（声明任一 = 嵌入条目，chat 路由零感知），未声明组 = 单例组（安全默认：不与其他厂商互换，厂商故障显式报错并附 `POST /admin/embedding-pins/{abstract}/reset` 恢复指引，禁止静默跨向量空间回退）。三层防护：① 配置校验（加载与热载共用 `validate_config`）——同组 upstream `model_id` 大小写不敏感一致、同组已声明 `dimensions` 相等、组名不跨 `abstract_id`，违反即拒绝；② 组粘着路由——嵌入候选按厂商类型过滤（该 abstract 下非 openai 型厂商不参与选择与 pin：protocol_error 不回馈熔断，不过滤会被首写 pin 投毒成永久失败）；pin 组候选全不可用显式失败（不跨组回退），组内故障迁移复用既有 fallback/fail-open 零新机制，并发首写竞态败者在胜出组内重路由、遗留 pin（组已无成员）自愈重选、`X-Vendor` 直连/全局池策略不参与 pin；③ 响应维度守门——无 `dimensions` 参数请求的首见响应维度记录为基准，同 (vendor, model) 后续响应维度漂移 → 502 拦截（向量不落客户端，错误体含 vendor/model/新旧维度与重置指引；batch 响应逐元素校验；带 `dimensions` 参数的请求不写记录不比对；base64 编码响应不解码守门，debug 日志显性化跳过）。生命周期：配置应用成功（落盘写回 + 热载桥接，经 `ConfigManager` 新增 swap hook 注册表在两条 apply 成功路径统一触发；校验失败不触发）清空全部 pin 重新粘着；新端点 `GET /admin/embedding-pins`（快照）/ `POST /admin/embedding-pins/{abstract_id}/reset`（单条幂等重置，级联清除该 abstract 各候选条目的维度守门基准，仅实际移除计数）；`/admin/metrics` 快照新增四计数 `embedding_pin_set_total` / `embedding_pin_reset_total` / `embedding_group_exhausted_total` / `embedding_dimension_mismatch_total`（reset 计数为双源：admin 单条 +1、热载清空按条数）。测试覆盖：路由四形态（无组粘着/厂商不可用不回退/组内迁移/两组独立）+ 热载重粘 + admin 列表/重置/重粘 + 维度漂移拦截/参数旁路 + chat 零感知回归守卫。

### Changed

- **难度定档规则参数配置化**：`[routing.difficulty.lexicon]` 新增 `hard` / `easy` / `math_symbols` / `question_marks` / `code_fence_markers` 五个可选列表，`[routing.difficulty.scoring]` 新增 14 个规则计分权重/封顶；缺省值与原源码常量逐位一致（无配置文件行为不变），显式数组整体替换内置默认。全部字段随 `[routing.difficulty]` 热读；决策缓存键纳入决策相关配置指纹，阈值/权重热更立即生效（不再等待 `cache_ttl_secs`），词法表变化经各信号命中数进入特征键。`MAX_TEXT_CHARS` 仍为源码常量（vecboost token 预算技术契约）。

- **嵌入多厂商配置默认行为变更（安全默认）**：存量「多个厂商配置同一抽象嵌入模型」的部署，`POST /v1/embeddings` 不再每请求跨厂商随机分担，而是粘着首次选中的厂商（保证同一向量空间）；被粘厂商故障时显式报错（不再静默换厂商产出可能不兼容的向量）。需要跨厂商负载分担/故障迁移的，给相关厂商的模型条目声明同名 `compat_group`（同组 = 承诺同模型同维度、向量可互换，配置校验强制）；单厂商嵌入配置行为不变。详见 Added「嵌入兼容组路由」。

- **BREAKING 项目更名 NexusFlow → Fluxgate**：crate/bin/lib `nexusflow` → `fluxgate`、examples crate `nexusflow-examples` → `fluxgate-examples`；错误类型 `NexusFlowError` → `FluxgateError`；环境变量前缀 26 个 `NEXUSFLOW_*` → `FLUXGATE_*`（含 `NEXUSFLOW_LANG` → `FLUXGATE_LANG`、`NEXUSFLOW_MASTER_KEY` → `FLUXGATE_MASTER_KEY`）；数据/配置目录 `~/.nexusflow/` → `~/.fluxgate/`；仓库地址 `Kirky-X/NexusFlow` → `Kirky-X/fluxgate`（GitHub 远端仓库同日完成改名，本地 remote 与本机 `~/.fluxgate` 主钥迁移已随之执行；徽章/克隆地址经旧地址重定向全程可用）。**升级必读的五处破坏面**：① vault 柜文件魔数随品牌改为 `FLUXGATE-VAULT1`，存量 `~/.nexusflow/vault.bin` 拒读（魔数不匹配）——厂商密钥若由 `api_key_env`/`api_key_envs` 指向，首装 env 吸收自动重灌；仅经管理端录入且无 env 备份的密钥需重录；主钥文件为纯 hex，`mv ~/.nexusflow/vault_master.key ~/.fluxgate/` 可直接迁移；② KDF 域分隔常量随名改写并恢复 32 字节约束（改名首次清扫曾把它缩短为 31 字节触发 cocoon 运行时 panic——已修复并补 `kdf_seed_is_32_bytes` 钉住测试，该 panic 是编译期不可见的纯运行时面）；③ shell profile / `.env` 中 `NEXUSFLOW_*` 导出与 `image: fluxgate:${FLUXGATE_IMAGE_TAG:-0.1.0}` 等部署引用需手改；④ 回退观测响应头族 `x-nexusflow-{vendor,model,attempts,fallbacks}` → `x-fluxgate-*`（`[resilience].expose_fallback_headers=true` 时 wire 可见）与分账过滤请求头 `x-nexusflow-cost-key` → `x-fluxgate-cost-key`；⑤ `GET /v1/models` 目录独有条目 `owned_by` 值由 `"nexusflow"` 改为 `"fluxgate"`（读models 的客户端若按该值过滤需随改）。全仓 1646 处旧名出现点（大小写不敏感口径，1538 行 / 214 个文本文件）一次性清扫，`git grep -in nexusflow` 除本条历史记录外零残留；`cargo fmt/clippy --all-targets -D warnings/test --workspace` 全绿。logo 已同步重绘为 Fluxgate 品牌视觉（`docs/assets/fluxgate.png`：流形 F 渐变图形 + fluxgate 字标），引用路径随改名切换。
